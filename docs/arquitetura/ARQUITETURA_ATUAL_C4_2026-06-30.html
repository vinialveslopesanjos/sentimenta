Arquitetura C4 e fluxo principal

Documento gerado em 2026-06-30 com leitura do repositório local e verificação read-only da VPS de produção. A análise diferencia evidência confirmada, inferências de alta confiança e pontos não encontrados.

FastAPI Next.js 15 Vite PWA Celery + Redis PostgreSQL 16 Docker Compose VPS srv1377371 Commit prod 4ce5a06

1. Resumo da arquitetura encontrada

  • O Sentimenta é um SaaS de análise de reputação digital com frontend web Next.js, PWA Vite/React, backend FastAPI, workers Celery, Redis e PostgreSQL.
  • O deploy de produção confirmado roda em uma única VPS Ubuntu 24.04.4 via Docker Compose, projeto sentimenta.
  • O Nginx fica na borda e encaminha /api/ para a API local, / para o Next.js e /app/ para a PWA estática.
  • O pipeline principal é assíncrono: a API cria um PipelineRun, publica tarefa Celery no Redis, o worker ingere dados, chama provedores externos, roda LLM e persiste resultados.
  • Redis é broker/result backend do Celery e também cache, rate limit, blacklist JWT e estado temporário de OAuth.
  • PostgreSQL é a persistência principal para usuários, conexões sociais, posts, comentários, análises, runs, créditos, Stripe events, demographics e blog.
  • Integrações confirmadas: OpenRouter/Gemini, Apify, Instagram Graph/OAuth, TikTok OAuth/API, YouTube Data API e yt-dlp, Stripe, Resend, Google OAuth, Sentry, Clarity/Google Tag.

2. Evidências e premissas

Confirmado no código

Routers FastAPI, modelos SQLAlchemy, Celery Beat, pipeline tasks, compose de produção, workflows de deploy, Nginx e dependências runtime.

Confirmado na VPS

Containers api, web, worker, beat, postgres e redis; API/web healthy; Nginx roteando Sentimenta.

Inferido com alta confiança

Deploy atual em uma VPS única; PWA servida como artefato estático; Redis centraliza fila, cache e estados temporários.

Não foi encontrada evidência runtime de S3/R2/GCS, NoSQL, Kafka, RabbitMQ, SQS, WhatsApp/Twilio, Kubernetes, Helm ou Terraform. Variáveis SUPABASE_* existem na VPS, mas não houve uso runtime encontrado no código atual.

4. Diagrama de fluxo principal - Mermaid

Fluxo escolhido: sincronização/análise de uma conexão social, porque é o caminho que entrega a promessa central do produto. 

sequenceDiagram
  autonumber
  actor User as Usuário
  participant Web as Next.js/PWA
  participant API as FastAPI
  participant Redis as Redis/Celery
  participant Worker as Celery Worker
  participant DB as PostgreSQL
  participant Social as APIs sociais/Apify
  participant LLM as OpenRouter/Gemini
  participant Email as Resend

  User->>Web: Clica em sincronizar/analisar conexão
  Web->>API: POST /api/v1/connections/{id}/sync com JWT
  API->>Redis: Verifica rate limit e estado temporário
  API->>DB: Valida conexão, plano, créditos e run ativo
  API->>DB: Cria PipelineRun status=running
  API-)Redis: Enfileira task_full_pipeline(run_id)
  API-->>Web: Retorna task_id, run_id e status inicial

  loop Acompanhamento no frontend
    Web->>API: GET /api/v1/pipeline/runs
    API->>DB: Lê PipelineRun do usuário
    API-->>Web: Status, passos e contadores
  end

  Redis-)Worker: Entrega task_full_pipeline
  Worker->>DB: Carrega usuário, conexão e PipelineRun

  alt Instagram OAuth
    Worker->>Social: Busca mídia/comentários via Instagram Graph
  else Instagram público, TikTok ou enrichment
    Worker->>Social: Executa actors Apify
  else YouTube
    Worker->>Social: Usa YouTube Data API ou yt-dlp
  end

  Social-->>Worker: Posts, comentários, métricas e mídia
  Worker->>DB: Upsert posts/comments e atualiza passos do run

  loop Batches de comentários pendentes
    Worker->>LLM: Envia comentários/contexto para análise
    LLM-->>Worker: Score, polaridade, emoções, tópicos, custo
    Worker->>DB: Grava comment_analysis e summaries
  end

  Worker->>DB: Consome créditos conforme comentários analisados
  Worker->>Redis: Invalida caches do dashboard
  Worker->>DB: Marca PipelineRun completed ou failed

  opt Run concluído com sucesso
    Worker->>Email: Envia notificação de sync
  end

  Web->>API: Busca dashboard/conexão atualizados
  API->>Redis: Tenta métricas em cache
  API->>DB: Consulta dados persistidos se necessário
  API-->>Web: Dashboard com dados reais do run
  Web-->>User: Exibe resultado e histórico rastreável
