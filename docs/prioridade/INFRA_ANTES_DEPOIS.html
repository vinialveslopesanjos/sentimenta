A produção já está rodando em Docker. Este painel mostra o que mudou, o que o PR oficializa no Git e quais decisões ainda precisam de aprovação.

Depois Docker Compose

O que acontece se aprovar o PR #31?

Não deve fazer deploy automático para produção.

O Sentimenta já foi migrado direto na VPS. O merge do PR coloca no `main` os arquivos que representam essa nova realidade: Docker Compose, Dockerfiles, CI, testes, runbooks e docs. O ganho é governança: próximas mudanças passam por GitHub Actions antes de virar padrão oficial.

Precisa decidir ou aprovar

Ordem sugerida para continuar agora.

1. Aprovar e mergear o PR #31

Recomendado. CI passou e isso alinha o Git com a produção que já está rodando.

2. Rotacionar o token XPoz

Importante. Um token antigo estava hardcoded em script legado. O arquivo atual foi limpo, mas o segredo precisa ser trocado no provedor.

3. Fechar ou manter a porta SSH 22

SSH por senha já está desligado. A decisão é se mantemos 22 e 2222, ou se deixamos só 2222.

4. Decidir destino do Postgres antigo no host

O Sentimenta usa Postgres Docker agora. Antes de desligar/restringir o antigo, precisamos mapear se outros projetos ainda usam.

5. Definir estratégia de `.env.enc`

SOPS/age faz sentido, mas só se a chave privada ficar fora do Git e fora do mesmo lugar do `.env.enc`.

6. Repos separados e Kubernetes

Ainda não é urgente. Monorepo + Docker Compose é o melhor próximo passo. K3s ou repo separado para ETL fazem sentido depois que o motor tiver contrato próprio.
